# 学生私人工作台：画像、诊断与 Agent 过程体验任务

**状态：**产品决策已确认，待分工设计与实现；**不是当前运行能力说明**
**确认日期：**2026-10-14
**范围：**`cpa-xingtu` 的学生职途导航、能力画像、简历诊断、Agent 对话及其共同的任务/成果状态。
**依据：**学生画像、简历内容、Agent 对话和职途导航的五张运行截图，以及本轮逐项确认的产品讨论。

## 1. 产品定位与核心原则

- 当前面向**学生本人**的私人工作台。诊断、候选分数、补充回答与 Agent 执行过程不默认作为教师或招聘方可见材料。未来分享需另做可预览、可选择内容的版本，不直接外发工作台。
- 学生第一眼应看见「目前能得出什么结论、依据是什么、哪里仍未知、下一步做什么」，而不是内部字段、巨量原始条目或貌似完整的空骨架。
- 结果应直接、诚实地表达现实判断，包括院校背景与职业门槛；同时严格区分**有不利证据**与**没有足够证据**。不以保护性空话回避判断，也不把缺证据伪装成低能力。
- Agent 过程**保留可见且只读**。借鉴开发型 Agent 工具的连续事件流、实时状态与可复盘性，但不把职业产品整体做成 IDE。
- 本文是目标契约。当前 HTTP 链路、`partial`/`completed` 门禁、来源审核、隐私和后端队列实现仍以运行行为及现有文档为准；任何目标与现状冲突都必须作为待办验证与迁移，不能只改文案宣称已实现。

## 2. 信息分层：默认看、深入看、不展示

| 层级 | 内容与表达 |
|---|---|
| 默认主任务区 | 当前任务与成果的准确状态；简短、有证据的能力解读；最重要的优势、限制和一个下一步行动。部分画像也先提供可用结论，不用三张后端 KPI 卡占满首屏。 |
| 结论附近展开 | 对应原文、页码、资料版本、推断依据与纠错入口。候选数字分数及其范围/限制可在评估依据中查看；未形成的分数保持未知，不显示 0 或综合分。 |
| 我的资料/证据 | 按原简历顺序完整保留项目、竞赛及技能词，不在画像正文重复一整份简历。项目优先呈现本人贡献与结果；未知时不编造。赛事级别与实际获奖分开；「简历提及」技能与有经历支撑的技能分开。 |
| 只读过程视图 | 当前任务的真实 Agent/工具调用逐条按时间出现，**不把多次同类调用合并成一条摘要**。每条以「做了什么」为主标题，工具或 Skill 原名为紧邻的次级标签；可展开实际记录、状态、时间和可展示的输入输出。 |
| 不进入学生界面 | 密钥、系统提示、模型私有思考草稿、其他用户数据；与学生任务无关的基础设施遥测。不伪造市场热度、录用概率、奖项或能力分。技术名称本身不承担唯一解释职责。 |

只读过程视图的「原始记录」指真实执行事件，不是再加工的一层摘要。敏感字段应单独遮蔽，不得以遮蔽为由抹掉整条可观察事件。是否具备可安全呈现的原始输入输出须由后端状态/隐私契约证明，不能把当前仅有元数据的轨迹冒充完整记录。

## 3. 页面与交互组织

- 桌面端采用**一个主任务区 + 常驻过程栏**，不再是三个同权重的内容列。过程栏跟随当前打开的任务；其他运行任务在任务列表显示状态，切换后再看对应过程。
- 手机端主任务区占满可读宽度，过程有明确且随时可达的入口，点开是同一任务的只读过程视图；不把常驻双栏硬塞到窄屏。
- 聊天对话与过程观察是两种不同界面，但引用同一任务、事件和成果状态。聊天可解释、追问并深链到当前报告/画像，不另造一个相互矛盾的「聊天版画像」。新事实进入明确的资料更新与重新分析流程。
- 无运行任务时，主任务区也不退化为空白聊天框：无资料时引导导入；画像仍有未知时展示当前结论与一个最值得补充的问题；已有结果时展示最新成果与下一步探索。聊天入口保持可用。
- 保留现有品牌身份，重点重排主任务区、过程栏、字阶与密度；不要只换颜色。部分画像的星图是紧凑的辅助预览，信息足够时才可成为主视觉；未知维度不能画成零分。
- 简历诊断报告先给可读摘要（简历传达了什么、最值得改什么、哪里未知），再进入分章节的完整事实和证据；不以 40 条记录长滚动开场。画像首屏也只引用能支撑结论的少数相关事实。
- 自述补充不默认摆出四组泛化表单。Agent 结合现有资料一次提出一个具体问题，可跳过；回答先明确标为用户自述，再由学生选择「保存并更新画像」，之后显示受影响的结论及来源变化。
- 学生可以在结论附近指出「这条不准确」，入口需区分原文提取错误、解释错误和新增经历；不允许直接改写计算分数。

## 4. 任务、成果与版本状态

1. 导入简历或保存新版简历后，默认自动启动分析；学生可离开页面，任务继续运行。完成、失败或需回答时由任务列表给出真实状态和适度提醒；回来可接着查看同一任务，不靠用户回复「继续」解决模型预算/任务恢复问题。
2. 一次分析可产生**简历诊断报告**和**能力画像**两个成果，各有独立状态。「本轮自动处理结束」不等于两个成果都完整。四个 Agent 检查点的 `100%` 只能解释为那四步已提交，不能解释为画像完成或所有资料已核验。
3. 画像是否能形成当前结果，不以「四维全部有数字」或「所有原始条目逐一获学生点击」为门槛。已处理可用资料、关键矛盾已解决或明确留未知时，可形成当前画像；不能判断的维度如实写「证据不足」，不强制给分或综合分。真正未完成是后台仍在处理或有必须解决的关键阻塞。**这与现有 L2 `partial`/`completed` 门禁可能不同，须先做后端契约迁移与权威状态验收。**
4. 学生核验以**处理例外**为主：Agent 先整理可直接识别的事实，只在矛盾、歧义或会明显改变结论时集中提问；完整条目仍可查看和纠错，但不变成 40 次默认审批。
5. 当前结果和历史快照必须区分。新版资料分析期间，旧成果仍可读但标明「基于上一版资料」；新成果回读确认后才成为当前版本。聊天、页面和报告引用同一当前版本，不把旧分数混入新画像。
6. 简历诊断报告只在简历与已确认原文范围内宣称完成；画像允许存在未知维度；未有可信岗位专项来源时不产生正式匹配或岗位报告。三种完成语义不得互相替代。

## 5. 职业探索与上下文判断

- 部分画像也可进入**职业方向探索**：给出值得了解的方向、与本人资料的关联、职业本身的工作与要求，以及尚缺的关键信息；不称正式匹配，不排名，不给匹配百分比。学生也可输入自己的方向。
- 方向卡要分开「为什么建议你看」和「这个职业通常要求什么」；后者没有可靠资料时不写市场热度、竞争力或薪资断言。没有目标岗位时，画像不声称通用的「综合求职竞争力」。
- 院校背景等需要社会语境的判断，交由可调用、可维护的**上下文认知 Skill**提供分层常识与判断方法，例如普通本科、双非、双一流、211、985 的含义及常见招聘印象。Agent 应在基础背景中主动给出直接而有分寸的解释，不把学校标签放在姓名旁定义整个人，也不把社会印象伪装成官方资格事实或直接覆盖现有评分门禁。
