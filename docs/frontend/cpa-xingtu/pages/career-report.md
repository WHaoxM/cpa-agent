## 真实职途导航后的职业攀岩路径（2026-10-22）

- 重登恢复仍按本人方向列表读取既有探索及最新分析回合，不自动生成、不从历史正文挑一条可显示的结果。`created_at` 排序依赖写入连接时区一致：任务提交、派发／租约读取和对话幂等使用原 UTC 事务，结束后须恢复借入连接的原时区，避免后建探索早 8 小时、误选过期记录；不放宽 owner、来源或内容版本门禁。回放必须核对重登前后 exploration/turn、确认简历、自述修订、画像及解读来源相同，新增分析请求数为零。详见原页面验证报告的本轮恢复补记。
- 主入口是职途导航确认后的“03 · 职业攀岩路径”，不是前置岗位舆图。简历报告也可带方向名称进入 `/app/student/career-report?role=...`；名称只供选择，后端重新验证本人和实际目录。没有同名方向时请学生明确选择，不模糊映射。
- HTTP 模式复用本页原墙面纹理、螺栓、岩点、绳索、人物、D3 分组气泡和分栏，不用另一套普通列表替换。本人画像与简历解读从工作台的当前确认版本读取；读取失败或版本不一致分别提示，不能拼接旧新资料。四维未知保留未知，不换算成原演示七维分。
- 墙上连接“本人经历 → 优先下一步 → 想探索的方向”，表达探索顺序，不是晋升等级或胜任距离。人物固定在本人经历，不随目标选择攀到某个职级。基线晋升链曾因调用不存在的 `execute` 而返回 fallback，现改用客户端实际的 `execute_query`；真实 Neo4j 的“数据分析”参考链仍为空，不用演示晋升/转岗节点补齐，正式晋升参考仍未验收。
- 学生主动点击“看看我从哪里开始”才使用现有探索分析队列；选方向本身只读。起点、经历联系、关键问题与一个优先行动先展示，依据可展开；不要求先填投入时间或生成计划。继续讨论/实践使用现有探索功能，不另造任务系统。
- 既有 `GET /api/career/explorations` 支持可选 `role` 筛选和 owner-scoped 有效解读摘要；分析结果增加可选 `positioning`。其依据由服务端提供，不能由模型创造引用。旧结果仍可回看，不补造新结构；来源变化时不再显示为当前结果。失败保留本人问题，不自动重复提交。
- 再次进入可从本人最近方向接着看，刷新/重登回读 MySQL。账号、方向及组件代次共同约束列表、详情、提交和轮询；迟到响应不能恢复其他账号或方向。岗位不在目录、服务缺迁移和队列未运行均显示真实状态。
- 桌面保持原攀岩与双内容分栏，长解读在有界区域滚动，不能撑走气泡或遮住本人起点。窄屏保留完整墙面，顶部提供“攀岩路径／我的起点与下一步／本人画像与经历”定位，触控不少于44px；岩点和节点支持键盘，不依赖悬停。减少动态时不启动持续移动；真实人物不执行原演示的自动攀登。
- HTTP 隐藏没有真实保存能力的编辑、模拟生成/保存、演示匹配分、薪资、已掌握/未掌握及导出。显式 Mock 与旧成果物入口保留原职责，不把它们计入真实路径通过。
- 解读可以为 `needs_clarification`：实际经历原文与可用下一步保留，已识别的无据实现判断不发布；正文和结构化起点使用同一份校验结果。它不是完整判断或模型质量通过，不能因引用 ID 合法就认定句义有依据。自述展示只投影学生文字，不泄露任务、修订等内部元数据。

### 个人解读内容契约第4版（2026-10-23）

第4版保持第2／3版的原文锚点、所有权和来源边界；个人解读只生成一份positioning，普通正文及兼容比较由同一结果投影，不让模型先写三份不同的判断。未知项可以为空，不为栏目或篇幅凑技术问题。正文、联系、未知、下一步及理由中的已知错误一起进入原有**至多一次纠正**；不再丢掉坏的可选段落后冒充部分完成。禁止用假想例子补问题，也不把经历阅读写成“是否构成某种实践”的考核；报名计数不证明喜好、资源合理性或实际到场。

同一计数片段也不能借未引用的核对动作，解释成已找出哪些重复报名。当前原报告问题若被模型逐字重复到未知项，只有文字相同（兼容引号样式）、同一片段、无附加字段时才合为原来源问题，公开内容与不重复时完全一致；改字、添加例子、错引用仍失败。这是消除重复呈现，不是删掉一条无据建议。模型侧示例已统一choice协议，原一次native纠正不重复自由JSON示例；任务输入复用既有投影与预算，未调大额度。

已明确片段与待澄清片段分开：当前原解读summary引用能精确映射本回合原文时，起点只从这些已明确片段选择；不能把待问的“核对重复”解释成同一人报同一／不同活动等范围。待澄清片段仍用于原开放问题，学生回答后按新来源讨论。每段正文、联系、未知、动作及理由只用它自己的已验证引用执行内容检查，不能借另一段经历的到场记录解除报名范围限制。Schema仅限制实际可选片段，模型解释仍真实生成，不改写已保存旧结果。

已回答职责和规则、明确没讲解过结果且询问下一步用途的既有窄识别，同时约束首轮和一次纠正的回应范围：解释如何说明已有结果及其直接用途，不重跑查询、改规则或另设异常检查。不是给模型注入固定答案；动作和理由仍实际生成并校验。旧第2版结果保留历史可读，不自动重新生成或改写。

初次看起点且明确不生成计划时，若本人当前简历解读已有来源核验的问题，服务端将它与本回合的同一原文片段绑定。模型要先澄清时只选择内部choice，不重写问题或理由；公开结构仍是原有text／reason及依据，显示同一个开放问题。旧版／不可用解读、片段不一致或没有可用问题不启用此交接，不回退到一条固定提问。未说明不是“没做过”：原文没有本人否认时，生成端不提供not_done位置；所选问题的缺口说明由同一来源投影，不靠模型改标签。

学生回答后不再提供初次问题选项；下一步仍由模型生成。内部实践理由以reader_gain表达学生／听者具体能明白什么，公开仍兼容reason。原一次纠正的生成Schema约束不再添加例子或示例数字，原文引用、ID和学生实际数字不受此约束，不对正文做删句替换。早期第2／3版问题及理由仍可作为历史讨论续读，但不升级为当前第4版成果或学生事实。

- 不改原攀岩构图；起点先展示实际原文短句，再解释这项任务有什么用。模型只选服务端已读的依据／片段ID，由服务端回填原文，不能把“独立写查询”改成“独立完成整个项目”。项目名不作为本人行动，团队功能也不证明本人职责。
- 起点、经历联系、未知项、下一步和理由均校验；本人明确未做过的项只展示对应否认原句，不扩大成能力不足。解释不新增本人动机、实现方式、能力等级或准备程度，不编示例人数，不把报名人数改成实际参与人数。
- 下一步只保留一件事，既有 `question` 在新个人解读中不再额外显示竞争问题；需要追问时由下一步文字和原补充入口承接。说明重复判定方式后，不继续盘问理想边界，优先用已有结果做一次简短说明；此尝试不是能力验证。
- 内部模型草稿有 `anchors`，公开结果不暴露它；新生成`positioning.content_version=4`，分析回合沿用`content_status=current|legacy`。旧回合原文不改、标记旧版并可手动重新解读，不作为当前摘要，也不自动生成新任务。正文客户端读取同一投影结果。
- 继续复用现有QA、预算和最多一次纠错；引用合法、结构通过不等于内容通过。真实模型逐句评审、浏览器及未通过案例见[原报告内容收紧补记](../../../reports/2026-10-22-career-exploration-practice-replay.md#职责不扩大下一步说人话2026-10-23)。

### 职责澄清的连续性（2026-10-23）

不改变上述第2版事实边界与页面设计。起点仍最多引用2项，限制从实际Pydantic模型提取供首轮及原有一次纠错使用；错误反馈指出具体字段，不放宽引用上限、不回显整份无效候选。解释不能把“核对”认定为人工或自动处理；原文确有人工操作时仍逐字保留，未知做法可以询问。新个人起点的外层 `question` 必须为null，问题只由已校验的下一步承接，避免另一个未显示的问题竞争或改变讨论。

继续讨论时，从原v2结果恢复已问的下一步及其理由，放在此前讨论中，不提升为学生事实。针对已复现的重复报名澄清，仅当本次学生明确共同归属查询／核对的编写、给出判定规则、明确尚未讲解结论并询问下一步用途时，不再把实现方式问卷作为优先动作；模型仍需生成有依据的小尝试及理由，不注入固定答复。查询由本人、核对由同伴或未交代规则等情况不能套用该推进条件。这是有界已回答项校验，不是通用语义判真或能力认证。

不能用“例如”包装虚构的具体报名故事、姓名或重复案例；下一步只让学生使用已有统计及真实记录，未发现重复也可如实说明。下一步文字、理由和已回答项的已知错误同时反馈给原有一次纠错，不通过删句／改词或额外重试使其看似通过。

实际模型候选、拒绝／一次纠错、逐句内容复核与完整回访以[同一页面验证报告](../../../reports/2026-10-22-real-page-experience-repair.md#真实模型职责澄清修复2026-10-23)为准；技术走通但仍反复追问的轮次不能写成内容通过。

无新增迁移；现有探索陪伴仍依赖 `0018_exploration_analysis` 和 `cpa.agent` worker。隔离完整回放明确使用 0018；本任务早期正常库为0017，2026-10-23最终只读审计已为0020，属并行环境变化，本任务未升级或重载共享服务。没有将隔离成功扩写为变更后的正常账号写入已验收。实际回放、截图、失败与清理见[同一职业探索报告补记](../../../reports/2026-10-22-career-exploration-practice-replay.md#职途导航接回职业攀岩路径)。下方演示与历史接口说明不作为本轮真实接线表。

## 当前响应式呈现（2026-10-21）

- 桌面（宽度 ≥1024px）保留左侧实体攀岩墙，右侧依次为岗位概览、嵌套气泡/七维雷达、双栏成长计划；攀岩栏宽度为 `clamp(320px, 29vw, 420px)`。
- 小于 1024px 时，分析主体在同一个区域纵向滚动：攀岩路径 → 已选岗位概览 → 岗位气泡 → 七维能力差距 → 成长计划。攀岩图沿用 `400:900` 比例；未选岗位的空状态为约 256px，可点击“选择目标岗位”定位至气泡区，不再提示手机用户点击不可见的“右侧”。
- 手机顶部分两行展示模式/身份和报告操作，底部展示来源及操作，主要按钮至少 44px；编辑模式为工具与输入区在前、预览在后，输入字号 16px。
- 分析/编辑往返重建气泡画布并清理旧 simulation/observer；切换岗位保持所选岗位联动。岩点可点击或用 Enter/空格查看完整技能，详情可显式关闭；SVG 悬停不使用会覆盖坐标的 CSS transform。
- `prefers-reduced-motion` 下停止持续气泡运动和攀岩入场动画。样式及雷达配色限定在本页，不变更评分、报告数据、API 或其他页面主题。
