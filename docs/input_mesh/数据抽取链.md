### 📝 架构深度解析

#### 1. 物理解析层 (Physical Parse Layer) —— 契约的基石

- **实现逻辑**：根据你契约中的 `lossless_requirements`，该层不仅做 OCR，更核心的任务是 **Block Taxonomy（块分类）**。
- **学术/竞赛亮点**：引入“空间位置感知”。利用 MinerU 提取的 `bbox`，在分块时保留物理坐标。如果一个块被归类为 `PROJECT_EXPERIENCE`，则后续 LLM 抽取的实体必须位于该块的坐标范围内，这在学术上称为 **Spatial Grounding**，极大降低了幻觉。

#### 2. 隐私守卫与符号化预处理 (Privacy & Symbolic Layer) —— 降维打击

- **实现逻辑**：严格执行你契约中的 `privacy_guard`。在 LLM 介入前，先用符号层（Regex/AC 算法）锁定 `PHONE`、`EMAIL` 以及 **技能词 (Skills)**。
- **架构优势**：
  - **预先打标 (XML-Tagging)**：不再让 LLM “寻找”技能，而是让它“确认”关系。例如，输入变为 `“我在 <proj>Vapp</proj> 项目中使用了 <skill>FastAPI</skill>”`。
  - **脱敏一致性**：通过 `HMAC_SHA256` 处理 `STUDENT_ID`，确保在多轮对话中，同一实体的 ID 保持一致，但对 LLM 保持黑盒。

#### 3. 不确定性引导推理核 (Uncertainty-Aware Core) —— 压榨 0.6B 的极限

- **实现逻辑**：针对小模型（0.6B）容易“胡说八道”的特性，加入 **Entropy-based Uncertainty Gate**。
- **核心创新**：如果 Qwen3 在输出某个 Token（如日期）时，预测概率分布非常扁平（即熵值高），系统会自动标记该字段为 `Low Confidence`，跳过直接写入数据库，转而进入 `LogicGuard` 的强制核查流程。
- **学术点**：研究小参数模型在受限 Schema 下的 **Calibration (校准度)**。

#### 4. 逻辑守卫层 (LogicGuard) —— 最后的防线

- **实现逻辑**：这是你契约中 `fallback_policy` 的逻辑化身。它利用一套**关系约束矩阵**进行验证：
  - *时间约束*：`start_date` 必须早于 `end_date`。
  - *类型约束*：`SKILLS` 字段中不应出现学校名称。
- **竞赛亮点**：该层将 LLM 的“概率输出”强行拉回“确定性逻辑”中。即便 LLM 输出格式乱了，符号层也能根据预定义的 `block_id` 将数据拼回正确位置。
