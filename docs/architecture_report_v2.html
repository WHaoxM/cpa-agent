二、6层管线架构 (含 Agent 层)

Layer 0: 数据摄入与解析 ├─ Resume: MinerU + YOLOv10 + Qwen3-0.6B-SFT (F1=0.964) ├─ JD: Excel 规则解析 + LLM 补充 → 过滤非IT岗位 (R-01) └─ SFT: Teacher(GPT-4o) → 500份 Gold → Qwen3 LoRA 微调 ↓ student_profile.json / job_posting.json Layer 1: 知识构建 ├─ IT技能骨架 (O*NET inspired, 6大类 24子类 ~500技能) + LLM 从 JD 填充 ├─ 岗位画像聚合: 同岗位 JD 合并 → 技能频次 + 学历众数 (≥10个) └─ 职业路径图谱: Neo4j 全量入图 (晋升≥3链 + 换岗≥5×2) ↓ skill_taxonomy / job_portraits / career_graph → Neo4j Layer 2: 画像生成 ├─ 学生画像: D1规则 + D2 Hybrid匹配 + D3/D4 LLM特征→规则评分 └─ 岗位画像: 四维需求提取 + 权重分配 ↓ student_portrait_4d / job_portrait_4d → MySQL + Milvus Layer 3: 匹配与分析 ├─ 4D匹配: D1硬约束 + D2 AC+Embedding + D3/D4加权 ├─ 技能差距: required - possessed → gap → 学习资源推荐 └─ 路径推荐: 图最短路径 + 技能重叠过滤 ↓ match_result / skill_gap / career_path → MySQL Layer 4: 报告生成 ├─ 职业发展报告: 6章 (模板直填70% + LLM并行解读30%) ├─ 学习路径: 短期/中期阶段化规划 └─ 导出: JSON → Jinja2 → HTML (ECharts雷达图) / PDF ↓ career_report.html / .pdf Layer 5: ReAct Agent (智能体核心) ├─ 对话管理: 多轮对话 + Redis Session + Milvus RAG 记忆 ├─ 工具调度: ReAct 框架自主决定调用哪个 Tool │ ├─ Tool 1: Neo4j 图谱查询 (Text-to-Cypher, 知识图谱可视化) │ ├─ Tool 2: MySQL 结构化查询 (画像/匹配/报告) │ ├─ Tool 3: Milvus 语义检索 (技能/JD/简历 RAG) │ ├─ Tool 4: L0-L4 管线触发 (简历解析/画像生成/匹配/报告) │ └─ Tool 5: LLM 推理 (职业建议/报告润色/自然语言回答) └─ 意图识别 → 工具选择 → 执行 → 结果组装 → 自然语言回复 ↓ 用户对话界面

三、Agent 架构 (ReAct + Multi-Tool)

智能体采用 ReAct (Reasoning + Acting) 框架，LLM 作为"大脑"自主推理并决定调用哪个工具，满足 R-11 智能体定义。

Tool 定义

Tool数据源功能触发场景

对话 + RAG 记忆

短期记忆: Redis Session — 当前会话上下文 (最近N轮对话)
长期记忆: MySQL conversation_history — 全量对话历史持久化

工作流: 用户输入 → Redis 取会话上下文 → LLM 意图识别 → ReAct 推理链 → Tool 调用 → 结果组装 → 回复 + 存储

ReAct 循环实现

核心模式 (参考 MiroFish report_agent.py):

for iteration in range(max_iterations):
  response = llm.chat(messages) — Thought (思考)
  tool_calls = parse_tool_calls(response) — 解析 <tool_call> XML
  if "Final Answer:" in response → return — 终止条件
  if tool_calls → execute_tool → inject observation — Action + Observation

容错机制:
- Tool Call 解析: XML 标签 + 裸 JSON 兜底 + 尾部 JSON 提取 (3 级降级)
- 冲突处理: LLM 同时输出 tool_call + Final Answer → 前2次拒绝重试, 第3次截断降级
- 强制收尾: 达到 max_iterations 后注入 FORCE_FINAL_MSG
- LLM 空响应: 注入 "请继续" 重试

二、v3.0 自进化智能体升维 学术创新

v3.0 为演进式设计，不破坏 v2.1 已冻结 Schema。竞赛阶段使用 v2.1；v3.0 模块上线后渐进激活。

升维一: Cron-Driven Autonomous Ontology（自组织知识网络）L1

核心: 系统从"被动响应"升级为"主动探测"
架构: Celery Beat (每周) → 爬取最新 1000 份 JD → AC 新词发现 → DeepSeek-R1 CoT 推理 → 图谱热更新
R1 推理输出: 拓扑坐标 + 前置技能链 + 替代/演进关系 + 热度预测
新边类型: PREREQUISITE (前置) / REPLACES (替代) / EVOLVES_TO (演进)
与 v2.1: 共存——v2.1 处理已入系统数据, v3.0 主动探测外部世界, 共享 Phase D 热更新
学术亮点: Continuous Knowledge Distillation — 持续从非结构化JD蒸馏结构化知识

升维二: Actor-Critic Reflexion Loop（审查智能体）L3

核心: Planner-Critic 零和博弈，消除 LLM 过度乐观
角色职责温度
Planner Agent基于图谱提出 1-2 条发展路径0.7
Critique Agent规则硬检 (学历/转移概率) + LLM 软审 (市场/趋势)0.2
循环: 最多 3 轮; REJECTED → 负约束累积 → 重规划; 3 轮仍驳回 → 保守路径兜底
透明性: critique_history 完整记录，前端展示"曾考虑但被排除的路径"
学术亮点: Reflexion (Shinn et al. 2023) + Constitutional AI 审查范式

升维三: Asymmetric Transition Probability（非对称转移概率）L1

核心问题: Jaccard 是对称的 (A→B = B→A)，但职场转型是非对称的
公式: P(S→T) = coverage(S,T) × exp(-λ × energy_barrier)
维度v2.1 Jaccardv3.0 Asymmetric
对称性对称非对称
成本建模无weeks × difficulty_tier
衰减函数线性指数衰减 exp(-λ·barrier)
时间估算无关键路径法 (并行学习)
示例: 前端→AI算法 P=0.04 (几乎不可能) vs AI算法→前端 P=0.61 (自然过渡)
论文潜力: "基于技能势能差的非对称职场跃迁算法" — 核心创新点
