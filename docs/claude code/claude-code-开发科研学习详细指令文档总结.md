# 使用 Claude Code进行开发、科研、学习的详细指令文档总结

##1. 文档目标与适用范围

这份文档面向三类场景：

- 开发：需求实现、排查 Bug、重构、测试、交付
- 科研：问题定义、文献梳理、实验设计、结果复现
- 学习：知识拆解、练习闭环、阶段复盘

目标是让你把 Claude Code 用成一个“可控、可验证、可复用”的 agentic 协作工具，而不是一次性问答工具。

---

##2. Claude Code 通用使用原则（高质量产出的底层框架）

###2.1 五段式任务指令骨架（强烈推荐）

每次发任务尽量包含这五段：

1) **目标**：最终要交付什么
2) **上下文**：相关目录、文件、数据来源
3) **约束**：不能改什么、技术边界是什么
4) **输出格式**：清单、表格、补丁说明、分步骤
5) **验收标准**：怎么判断任务完成

可复制模板：

```text
目标：
上下文：
约束：
输出格式：
验收标准：
```

###2.2先计划后执行

建议默认采用两阶段：

- 阶段A：先让 Claude Code 调研并给计划（不改代码）
- 阶段B：确认计划后再实施

推荐话术：

```text
先不要修改文件，先阅读相关代码并给我执行计划：
-影响范围
- 将复用的现有函数/模块
- 改动文件清单
- 验证方法
```

###2.3 输出必须可审计

要求 Claude Code 在输出中包含：

- 改动文件路径
-关键函数定位（文件路径 + 行号）
- 验证命令与结果
- 风险与回滚点

###2.4 小步快跑，降低返工

大任务拆成3~6 个子任务。每完成一步就验收一次，不要一次要求“从设计到上线全做完”。

###2.5 明确“不要做什么”

建议显式加上这些约束（按需选择）：

- 不新增依赖
- 不改 API 协议
- 不改数据库 schema
- 不做无关重构
- 不提交 commit（除非我明确要求）

##3. 开发场景指令手册

>目标：把需求从“想法”变成“可验证改动”。

###3.1 场景：新增功能

可复制指令：

```text
实现功能：<功能描述>
上下文：相关代码在 <目录/文件>
约束：不改 <接口/库/模块>
请按顺序执行：
1)先阅读代码并输出实施计划（不改代码）
2) 我确认后再实现最小改动
3) 实现后运行相关测试/构建
4) 最后给出改动摘要、风险点、回滚方式
验收标准：
- <标准1>
- <标准2>
```

###3.2 场景：Bug 定位与修复

可复制指令：

```text
请修复这个问题：<现象/报错>
复现路径：<步骤>
上下文文件：<路径>
要求：
-先给根因分析链路
- 再给最小修复方案
- 补充必要测试
- 输出修复前后行为差异
验收标准：
- 可稳定复现并修复
- 不影响 <相关功能>
```

###3.3 场景：代码审查（不改代码）

可复制指令：

```text
请只做代码审查，不修改文件。
审查范围：<目录/PR diff>
重点关注：
-逻辑正确性
- 安全风险（命令注入/XSS/SQL注入等）
- 性能瓶颈
- 测试缺口
输出格式：
- 严重问题（必须修）
- 建议优化（可选）
- 风险排序（高/中/低）
```

###3.4 场景：重构（行为不变）

可复制指令：

```text
请重构 <模块>，目标是提升 <可维护性/可读性/扩展性>。
约束：行为保持一致，不改对外接口。
流程：
1)先输出重构边界和风险
2)只做必要重构
3) 给出重构前后结构对比
4)运行回归验证
```

###3.5 开发场景通用验收清单

- 是否复用了现有实现而非重复造轮子
- 是否仅改了必要文件
- 是否包含可复现验证步骤
- 是否标注高风险改动点
- 是否给出下一步建议（可选）

##4. 科研场景指令手册

>目标：让研究过程可解释、可追踪、可复现。

###4.1 场景：研究问题定义

可复制指令：

```text
我在研究：<主题>
请先不要给结论，先帮我输出：
1)研究问题（Research Question）
2) 核心假设（Hypothesis）
3)关键变量（自变量/因变量/控制变量）
4)评估指标（Metrics）
5)可能的威胁有效性（Threats to Validity）
```

###4.2 场景：文献/资料梳理

可复制指令：

```text
请围绕 <研究主题> 做资料梳理。
输出要求：
- 已确认事实 vs 待验证假设
- 主流方法分类
- 每类方法的适用边界
- 我可以直接验证的最小实验建议
```

###4.3 场景：实验设计

可复制指令：

```text
请为 <研究问题>设计可复现实验方案。
必须包含：
- baseline方案
- ablation（消融）方案
- 数据划分策略
- 参数与随机性控制
-结果记录模板（字段级）
-失败排查路径
```

###4.4 场景：结果分析

可复制指令：

```text
这是实验结果：<表格/日志>
请按以下结构分析：
1)结论（Claim）
2)证据（Evidence）
3)反例/替代解释（Counter-Explanation）
4)置信度（高/中/低）
5) 下一轮实验建议
```

###4.5 场景：复现报告输出

可复制指令：

```text
请把当前研究整理成“可复现报告”，结构如下：
-目标与假设
- 环境与依赖
- 数据来源与预处理
- 实验步骤（可直接执行）
-结果与偏差分析
- 未解决问题与后续计划
```

###4.6 科研场景通用验收清单

- 是否把“事实”和“假设”分开
- 是否明确评估指标
- 是否包含可复现步骤
- 是否说明结论边界
- 是否给出下一步实验路径

##5. 学习场景指令手册

>目标：从“看懂”走向“会做”，形成持续提升闭环。

###5.1 场景：学习路径设计

可复制指令：

```text
我要学习：<主题>
当前基础：<入门/中级/进阶>
可投入时间：<每天/每周>
请输出：
-4周学习路线图（按周）
- 每周目标与产出物
- 每周自测题与通过标准
```

###5.2 场景：概念拆解与类比讲解

可复制指令：

```text
请讲解 <概念>，要求三层输出：
1) 小白版（直觉解释）
2) 工程版（应用场景 + 常见坑）
3) 面试版（高频追问 + 标准回答）
最后给我3道练习题。
```

###5.3 场景：代码练习与反馈

可复制指令：

```text
我会做这个练习：<题目>
你只做教练，不直接给最终答案。
流程：
-先给思路检查点
- 我提交解法后你做代码审查
- 指出错误并给改进方向
- 最后总结可迁移方法
```

###5.4 场景：错题复盘

可复制指令：

```text
这是我的错误解法：<内容>
请按“错因分类”帮我复盘：
- 概念错误
- 推理错误
- 实现错误
- 验证缺失
并给出下一次避免同类错误的清单。
```

###5.5 场景：阶段评估

可复制指令：

```text
请根据我最近两周的学习记录，做一次阶段评估：
- 能力增长点
- 薄弱项
- 下阶段重点
-具体行动项（每日/每周）
```

###5.6 学习场景通用验收清单

- 是否有明确产出物（笔记/代码/题解）
- 是否有量化自测标准
- 是否包含复盘机制
- 是否形成下一阶段计划

##6. 跨场景最佳实践与反模式

###6.1 最佳实践

1) **先边界后执行**：先说清“做什么/不做什么”
2) **先输入后输出**：提供足够上下文再要求高质量输出
3) **先计划后实现**：减少误改和返工
4) **先验证后结论**：所有结论应有证据链
5) **模板化复用**：把高质量指令沉淀成模板

###6.2 常见反模式

1) “帮我优化下这个项目”——目标太泛
2) “直接改完全部再说”——缺少阶段验收
3) “你看着办”——没有约束条件
4) “不用测试，直接提交”——高回归风险
5) “一条消息做完整产品”——任务粒度过大

---

##7. 推荐协作流程（开发/科研/学习通用）

### Step1：定义任务
用五段式骨架给出初始任务。

### Step2：只读调研
要求先读代码/资料，不立刻动手。

### Step3：计划确认
确认影响范围、改动清单、验证方案。

### Step4：执行与验证
分步骤执行，每步都给可验证输出。

### Step5：结果沉淀
把可复用模板、检查清单、结论边界沉淀到文档。

##8. 可复制模板附录

###8.1 通用模板（任务启动）

```text
目标：
上下文：
约束：
输出格式：
验收标准：
执行顺序：先调研 -> 给计划 -> 我确认 -> 再实施
```

###8.2 通用模板（只读分析）

```text
请只做只读分析，不要修改任何文件。
我需要你输出：
1)现状总结
2)关键问题
3) 可复用资源
4) 最小可行方案
5) 风险与验证方法
```

###8.3 通用模板（最终汇报）

```text
请按以下结构汇报：
- 已完成项
- 改动文件列表
-关键逻辑说明
- 验证结果
- 已知风险
- 后续建议
```

###8.4 开发模板（最小修复）

```text
请做最小修复，不做额外重构。
必须：
- 根因明确
- 改动最小
- 验证完整
- 输出修复前后差异
```

###8.5 科研模板（批判性检查）

```text
请对结论做批判性检查：
- Claim
- Evidence
- Failure Conditions
- Counter-Explanation
- Confidence（高/中/低）
```

###8.6 学习模板（教练模式）

```text
你做我的学习教练，不直接给最终答案。
先给提示和检查点；我提交后再做反馈与纠偏。
```

---

##9. 文档维护建议

- 文档顶部增加“最后更新时间”
- 高变动内容（命令、能力边界）定期复核
- 每次项目实践后，把有效提示词补充进模板附录
- 清理低复用、低成功率模板

---

##10. 一句话实践建议

把 Claude Code 当作“可编排的协作代理”：**任务边界清晰、输出可验证、过程可复用**，就能在开发、科研、学习三条线都稳定提效。
