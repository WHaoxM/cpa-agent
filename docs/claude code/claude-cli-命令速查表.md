# Claude Code CLI 命令速查表（开发 / 科研 / 学习）

>目标：快速知道“这个命令做什么、什么时候用”。

##0)先用这三个

| 命令 | 用途 |什么时候用 |
|---|---|---|
| `/help` | 查看当前可用命令与说明 | 不确定命令、版本更新后、刚进新环境 |
| `/model` | 切换模型 |任务复杂度变化（重推理/快迭代） |
| `/clear` | 清空当前对话上下文 | 对话跑偏、历史过长影响输出 |

---

##1) 开发场景常用命令

| 命令 | 用途 | 最佳使用时机 |
|---|---|---|
| `/init` | 初始化项目级说明（CLAUDE.md） | 新仓库/新成员接手时 |
| `/update-config` | 配置权限、hooks、环境变量等 |需要“每次自动做X”时 |
| `/simplify` |复查并精简已改代码 | 改完代码后、提交流程前 |
| `/review` |代码审查 | 提 PR 前 |
| `/security-review` | 安全审查 | 涉及登录、权限、输入处理、API改动后 |
| `/debug` | 调试 CLI 行为问题 | 命令异常、行为不符合预期时 |
| `/batch` | 拆分并行处理较大改动 | 多模块/大规模改动时 |

---

##2) 科研场景常用命令

> 科研场景重点不是“命令多”，而是“流程稳”。

| 命令 | 用途 | 最佳使用时机 |
|---|---|---|
| `/help` | 确认可用能力 | 开始新研究任务前 |
| `/model` |选择更适配的模型 |需要更强推理或更快迭代时 |
| `/clear` | 重置上下文避免污染 | 切换研究主题时 |
| `/debug` | 排查执行异常 | 自动化/工具调用异常时 |
| `/loop` | 周期性执行任务 | 定时检查实验状态、定期追踪指标 |

---

##3) 学习场景常用命令

| 命令 | 用途 | 最佳使用时机 |
|---|---|---|
| `/help` |了解当前命令 | 初学 CLI 时 |
| `/clear` |重新开始一个知识点 | 学习主题切换时 |
| `/model` | 调整体验与质量 |讲解深度需求变化时 |
| `/insights` | 会话分析与复盘 | 阶段学习结束后复盘 |

---

##4) 推荐协作流程（通用）

1.先 `/help` 看当前命令
2. 用结构化任务描述发需求（目标/范围/约束/验收）
3.先让 Claude 给计划，再执行
4. 改动后 `/simplify`
5. 敏感改动再 `/security-review`
6. 最后输出改动摘要、验证结果、后续建议

可复制任务模板：

```text
目标：
范围：
约束：
输出格式：
验收标准：
先不要改代码，先给计划。
```

---

##5) 新手高频误区

-误区：直接“全做完”
 - 改进：先计划、分步执行、每步验收
-误区：不给约束
 - 改进：明确哪些文件可改、哪些不能改
-误区：改完不复查
 - 改进：至少跑 `/simplify`，关键场景加 `/security-review`

---

##6) 一句话记忆

- **不知道用啥：**`/help`
- **对话乱了：**`/clear`
- **质量兜底：**`/simplify` + `/security-review`
- **想自动化：**`/update-config`
